# アーキテクチャ解説

このプロジェクトは「シェルスクリプト1本 + 指示書1枚」で動く、最小構成のAI秘書システムです。
ここでは、その内部でどう動いているのかを解説します。

## なぜ「シェルスクリプト + 指示書」だけで成立するのか

Gemini CLI には、**カレントディレクトリの `GEMINI.md` を自動で読み込む**仕様があります（Anthropic Claude Codeにおける `CLAUDE.md` と同じ発想）。

これによって：

1. シェルスクリプトは「`cd $VAULT_PATH` してから `gemini` を叩く」だけで済む
2. AIの挙動はすべて `GEMINI.md`（Markdown）に書ける
3. **指示書はエンジニアでなくても編集できる**

つまり、いったん仕組みを作ってしまえば、運用は**Markdownを書き換えるだけ**で完結します。

## ファイルの役割

### 入力側（あなたが書く）

| ファイル/フォルダ | 役割 |
|---|---|
| `GEMINI.md` | AIへの指示書。すべての挙動を定義 |
| `0_Thoughts/Daily/` | デイリーノート。会議メモ、思いつき、TODO候補など |
| `meetings/` | 会議の議事録 |
| `knowledge/` | 知識ベース |
| `projects/` | 各プロジェクトのまとめ |
| `Private/` `Not4AI/` | **AIに読ませない**フォルダ |

### 出力側（AIが書く）

| ファイル | 役割 |
|---|---|
| `gemini/daily-briefing.md` | **メイン出力**。今日やること、当日メモ欄、昨日の振り返り、提案 |
| `gemini/nord-map.md` | ナレッジマップ。ノート間のつながりを可視化 |
| `gemini/task-database.md` | 全タスクのデータベース |
| `gemini/project-database.md` | プロジェクト一覧 |
| `gemini/learning-from-feedback.md` | フィードバックから学んだことのログ |
| `gemini/archive/` | 過去のbriefingスナップショット |

## 安全設計

### 1. AIは既存ファイルを変更しない

`GEMINI.md` で **「既存ファイル・フォルダは一切変更しない」** を厳命しています。
書き込み先は `gemini/` フォルダだけ。万が一AIが暴走しても、あなたの既存ノートは無事です。

### 2. プライバシー保護

`Private/`、`Not4AI/`、`0_Thoughts/Daily/` は読み込み禁止です。
**個人的すぎる日記、機密情報、人事情報などは Private に置いておく**ことで、APIに送られません。

### 3. 出力ファイルの名前は固定

`daily-briefing.md` は**毎日同じファイル名**で上書きされます。
これは Obsidian でこのファイルをタブにピン留めできるようにするためです。
過去版が必要な場合は `archive/daily-briefing-YYYY-MM-DD-vN.md` を見ます。

## フィードバックループ

このシステムの最大の特徴は **「日々賢くなる」** ことです。

```
┌──────────────────────────────────┐
│ Day N: AIがdaily-briefingを生成   │
└────────────────┬─────────────────┘
                 │
                 ▼
┌──────────────────────────────────┐
│ あなたがbriefingにコメントを書く  │
│ 例：「タスクの優先度づけが雑」     │
└────────────────┬─────────────────┘
                 │
                 ▼
┌──────────────────────────────────┐
│ Day N+1: AIが昨日のコメントを読む │
│   ↓                              │
│ learning-from-feedback.md に追記 │
│   ↓                              │
│ 今日のbriefingで改善版を提示       │
└──────────────────────────────────┘
```

これにより、**外部にプロンプトエンジニアリングのノウハウを持たなくても、
日々のメモを書くだけでAIの精度が上がっていく**仕組みが完成します。

## モデル選択について

このテンプレートでは `gemini-2.5-pro` をデフォルトにしています。

| モデル | 特徴 | 用途 |
|---|---|---|
| `gemini-2.5-pro` | 高品質、コンテキストウィンドウ大（1M+） | ✅ 推奨。長いVaultでも一度に処理できる |
| `gemini-2.5-flash` | 高速・低コスト | 軽い処理 / 試運転 |

別のLLM CLI（Claude Code, OpenAI CLI など）に置き換えることも可能です。
詳しくは [customization.md](customization.md) を参照。

```
あなた

  ▼

  │ 読まれる
  ▼

  ▼

  │ 指示通りに
  ▼

  ▼

```

## このシステムが避けていること

- ❌ クラウドノートアプリへの全データアップロード
- ❌ 独自のフロントエンド（GUI、Webアプリ）
- ❌ 複雑なベクトルDBやエージェントフレームワーク
- ❌ 専用のサーバー運用

**「すでにあるツール（Obsidian + Gemini CLI）の組み合わせだけ」** で実現することにこだわっています。
これにより、**メンテナンスコスト=ほぼゼロ**、**他人への説明が3分で済む**形になっています。
